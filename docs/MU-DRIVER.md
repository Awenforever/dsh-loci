# μ 的驱动力

> 回答一个问题：**记忆单位由什么驱动？** 不是在问「时间是什么」，是在问「作为记忆空间的造物主，我们选择让什么推动它」。

## 0. 为什么旧公式是错的

旧公式：

```
每次事件： μ += log(w_add·add + w_use·use + 1)
```

实测数据（25.4 小时、59 条记忆的真实库）：

| 事件 | 次数 | 推动的 μ |
|---|---|---|
| 注入 | **1007** | 99.9% |
| 写入 | 48 | 0.1% |

结果是 **1 μ ≈ 1.07 分钟**，一天 1349 μ。

问题不在数值大小，在**驱动源选错了**。`use` 计的是「提示词里塞了几条记忆」，那是**机器在运转**，不是**世界在移动**。

一个比喻：旧公式等于用「我这台相机按了多少次快门」来当世界的时间。快门次数和世界的变化没有因果关系，只是同时发生。

**判据**：如果一次事件发生了，但 agent 对世界的理解完全没有变化，μ 就不该动。

## 1. 第一原则

记忆空间存在的目的（锚点，不可漂移）：

> **为了让 agent 更好地/更准地/更聪明地/更高效地/更强地完成任务，以及 agent 自身的成长与进化。**

于是 μ 的定义必须是：**这个 agent「需要一套不同的记忆」的程度，累积起来是多少。**

- 学到一件新东西 → agent 需要的记忆变了 → μ 动
- 反复读取已经知道的东西 → 它需要的记忆没变 → μ 几乎不动
- 世界变了、旧知识过时了 → 记忆的适用性变了 → μ 动得多
- 什么都没发生 → μ 冻结

这与 §2 的「`add = use = 0` 时 μ 不增长」一致，但它更严格：**不是「有没有操作」，而是「理解有没有位移」。**

## 2. 三个驱动源

不是三个计数，是三种**质不同**的变化。每个都有可观测的代理量。

### D1 增积（Accretion）：学到了新东西

每一次写入都推进 μ，但**推进量取决于它有多新**：

```
Δμ_write = log(1 + novelty)
```

`novelty ∈ [0, 1]`，1 = 全新，0 = 完全重复。于是：

- 写一条库里已有的规则 → `novelty ≈ 0` → **几乎不推进**。重复记同一件事不该让记忆变老。
- 写一条真正的新事实 → `novelty ≈ 1` → 推进 `log 2 ≈ 0.69`。
- 修正/取代一条旧记忆 → `novelty = 1`（定义如此：世界变了，这条记忆的适用性变了）。

**novelty 怎么算**（不需要模型）：

```
novelty = 1 − max_{existing} Jaccard(tokens(new), tokens(existing))
```

token 集来自标题 + 正文，用现成的 `tokenize.js`。取最近 200 条比较，n 很小时开销可忽略。

**为什么是 Jaccard 而不是余弦**：余弦需要 embedding，而 embedding 要调模型、可能没开。Jaccard 免费、永远可用、且对「几乎逐字重复」这类真正该记 0 的情况足够敏感。将来 embedding 可作增强，但对**这个**判据不是必需的——我们只需要区分「同一件事」和「另一件事」，不需要细腻的语义距离。

### D2 蚀变（Obsolescence）：世界移动了

一条记忆被 `update` 取代、或同一个 scope 下写了新的矛盾事实，说明**旧知识不再适用**。这是比「新增」更强的位移信号：不只是多了东西，是原来的东西**变错了**。

```
Δμ_supersede = log(2)         （一次取代 = 一次完整的位移）
```

D1 与 D2 的区别值得保留：新增一条规则和推翻一条规则，对 agent 的影响不同。后者要求它**忘掉**，前者只要求它**多知道**。

### D3 巩固（Consolidation）：证明有用的使用

被召回**而且真被展开**（`read_count` 增长，即模型去查了全文）说明这条记忆在做工。

但**巩固不推进 μ**。它推进的是**这条记忆自己的位置**（召回把它拉回栖息地），不是整个空间的钟。

> 这是旧公式最深的错误：它把「记忆被使用」和「时间流逝」混成一件事。**使用应该让那条记忆变年轻，不该让所有记忆一起变老。**

因此 D3 在 μ 方程里的权重是 **0**，它的全部作用在轴动力学里。

### D3′ 背景流（Baseline）：证明 agent 在工作

一次普通对话轮**不改变理解**，所以严格说 μ 不该动。但完全不动会让长期只读不写的工作永远不老化。

折中：每轮给一个**很小**的权重，代表「上下文在流动」。

```
Δμ_turn = w_turn · log(2),   w_turn ≈ 0.01
```

一天 200 轮 → 1.4 μ。它保证 μ 永不完全冻结，又不喧宾夺主（对比：50 次真实写入 ≈ 24 μ）。

**这不是墙钟**：没有对话就没有这个分量。它计的是「发生了多少次工作交接」，不是「过了多少秒」。

## 3. 方程

```
Δμ = log(1 + Σ novelty_i)            D1，本步写入的增积
   + log(2) · superseded             D2，本步取代了几条
   + w_turn · log(2)                 D3′，本步是否有工作推进
   + w_use · log(1 + use)            D3，使用，w_use ≈ 0.002
```

其中 `w_use` 小到几乎可以忽略，但保留它是因为「一个被反复检索的库说明工作在进行」确实是**弱**信号——弱到不该主导，不该为零。

## 4. 尺度：一天该有多少 μ

这是纯设计选择，但可以用一个可检验的句子定下来：

> **一天真正的工作，约等于 20–30 μ。**

依据：一天里人真正学到的新东西是有限的——几条规则、几个事实、几次修正。旧的 1349 μ/天 相当于「一天学到一千多件事」，那显然不是人的速度。

在新方程下，实测库（48 次写入、1007 次注入、25 小时）会得到大约：

```
D1: 48 次写入，平均 novelty ≈ 0.6 → Σ log(1.6) ≈ 22.6
D3: 1007 × log(1 + 0.002×3)        ≈  6.0
D2/D3′:                            ≈  3.0
                                    ─────
                                     ≈ 32 μ / 25.4 h ≈ 30 μ/天
```

**这个数字是算出来的，不是挑出来的**——它是新驱动源对同一段历史会产生的值。这同时给出了迁移因子：旧库 1425 μ ÷ 新算 30 μ ≈ **49**。迁移就是把存量除以 49，让旧数据的单位与新方程一致。

> 迁移因子不是为了让数字好看而选的；它是「如果用正确公式重放这段历史，计数会是多少」。这是一次**一致性检查**，不是化妆。

## 5. 轴参数随之重定

μ 的单位变了，`R` 与 `δ` 必须一起换算，否则动力学改变。

| 参数 | 旧值 | 新值 | 理由 |
|---|---|---|---|
| `R`（入口深度） | 2000 | **120** | 约 4 个工作日到栖息地、8 个到遗忘。旧值在旧单位下是 1.5 天，**对记忆来说太短** |
| `δ_base` | 130 | **10** | 保持「救援深度 ≈ R 的 5–6%」的相对比例 |
| `δ_scale` | 500 | **30** | 同上 |
| `δ_min` | 1 | **0.1** | 同上 |

救援深度 = 7 μ ≈ 一次工作日的四分之一（因为 30 μ/天）。换句话说：**一条记忆如果一天之内被用过，一次召回就能救回；放了一周，就得用很多次。**

`R` 从「1.5 天」改成「4 天」是一次**有意的寿命延长**：旧值是在错误的 μ 速率下定的，重算之后它短得没有意义。代价是迁移后的存量条目看起来比以前「年轻」——它们确实变年轻了，因为记忆空间本身变大了。

## 6. 这个设计仍有的诚实缺口

1. **novelty 用 Jaccard 是词面近似**，不认同义改写。「先校验路径再删除」和「删除前须断言路径」会被判成两件事。可接受，因为误判方向是**多推进 μ**（记忆略快老化），不是危险方向。
2. **D2 的自动检测不完整**：`update` 是显式的，但「同一 scope 下写了矛盾事实」系统不知道矛盾，只知道写了新内容。真正的矛盾检测需要模型。
3. **`w_turn` 的 0.01 是拍的**，没有测量方法——只能用「一天 200 轮给 1.4 μ」这个量级约束住，不让它变成第二个墙钟。
4. **「一天 20–30 μ」是设计目标而非测量结果**。它的依据是「人一天学不到一千件事」，这是个判断，不是数据。

## 7. 判据（可观测、可测试）

1. 连续 100 次注入、0 次写入 → μ 推进 < 1 μ；
2. 写一条与已有条目逐字相同的记忆 → μ 推进 < 0.05；
3. 写一条全新记忆 → μ 推进 ≈ 0.69；
4. 取代一条旧记忆 → μ 推进 ≈ 0.69；
5. 一次真实工作日（几十次写入 + 数百次注入）→ μ 推进 20–30；
6. 没有任何事件 → μ 完全不动。
