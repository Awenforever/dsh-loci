# 怎么看懂你的记忆库

> 给使用者的说明，不是给开发者。回答四个问题：**记了什么 / 什么在起作用 / 什么沉了 / 该我做什么**。

## 0. 先知道一件事

这个库**不记录"模型有没有照做"**。原因是它看不到任务结果——只能看到自己把哪些记忆放进了提示词。

所以本文件里所有"用上了"的说法，都严格指**"进过提示词"**，不指"起了作用"。凡是需要观测结果的判断，这里不会给，因为给了就是编。

## 1. 四个入口，各自回答一个问题

| 你想知道 | 用这个 | 一句话 |
|---|---|---|
| 最近记了什么、什么在反复出现、什么沉了 | `node scripts/journal.mjs` | 人的日记视图 |
| 它现在健康吗 | `node scripts/report-production.mjs` | 忆/记/时钟三块 + 一行结论 |
| 能不能投产 | `node scripts/diag/readiness.mjs` | 十项检查，全过才打印 READY |
| 某条具体记忆长什么样 | 面板 → Index / Search，或 `node scripts/cli.mjs search <词>` | 逐条查看 |

面板（对话右下角 Memory 卡片 → 展开）有四个页签：

- **Index** — 当前作用域里被注入的那一段，逐字就是你模型看到的
- **Search** — 全文检索
- **Review** — 等你批准的条目
- **Stats** — 计数、距离分布、最近推进

## 2. `journal` 的三段怎么读

```
最近 7 天记了什么
  16:52  相关时才出现   为兼容 quota 1.1.58，仍须同时发布…
  11:48  常驻          AGENTS.md 只留指针，不写案例细节或事故经过
```

每条前面那个词是**适用范围**，它决定这条会不会每轮都出现：

| 标记 | 含义 | 什么时候出现 |
|---|---|---|
| **常驻** | `applies: always` | **每一轮**都在提示词里 |
| **相关时才出现** | `applies: topic` | 只有你的问题匹配到它时才被检索出来 |

> 判据只有一句：**这条说的是「工作怎么做」，还是「某个东西该怎么弄」？**
> 「AGENTS.md 只留指针」是前者（常驻）；「位置切换图标不要用左右箭头」是后者（相关时才出现）。
> 对某个界面元素的硬性要求也属于后者——要求是硬的，但那个界面不是每个任务都碰。

```
一直在用的
    442 次  相关时才出现   位置切换图标不要用简单的左右箭头…
    256 次  常驻         最终验收必须亲自截图确认…
```

次数 = **它被放进提示词的次数**。次数高说明你的工作总在回到这件事。

**注意**：次数高不等于好。如果一条只在改图标时才该出现，却出现了 442 次，那是它**该沉下去但没有**——旧版本就是这样（所有规则都常驻），5.2.0 之后才分开。

```
沉底的
  （还没有条目沉底。从未被召回的 19 条仍在入口与消化区——
   要穿过整段 R 才会出现在这里，本库目前只走了 1220 μ）
```

「沉底」= **已经漂到栖息地左边，而且一次都没被召回**。这是位置，不是天数。

一个从未被用过的条目要穿过整段入口和消化区才会到这里；一个年轻库还没走那么远，所以这一段可能是空的——**空是有原因的，不是功能坏了**。

## 2.1 位置：那条带符号的轴

```
遗忘 ←—— − ——← 0 ←—— 修剪 ——← + ←—— 新记忆在这里落下 (+R)
```

| 区域 | 含义 |
|---|---|
| **入口** (`p > 0.6R`) | 新记忆落下处。变化极慢 |
| **消化区** (`0 < p < 0.6R`) | 向左滑行，越靠近 0 修剪越深 |
| **栖息地** (`p ≈ 0`) | 消化完成。**多数有用的记忆应在这里** |
| **压缩区** (`-0.6R < p < 0`) | 开始丢细节 |
| **遗忘** (`p < -0.6R`) | 只剩合并 |

三件事推动位置，**互不重叠**：

1. **写入** → 落在 `+R`（入口），不是栖息地。刚记住 ≠ 刚用过。
2. **时间** → 每个 μ 无条件左移 1。不碰它也会老化，这保证没有东西能被永久钉住。
3. **召回**（注入或读取）→ 向右移 `δ(p)`。0 附近幅度大（一用就救回），越远越小，但有下限（**任何位置都不会变成死路**）。

`doctor` 会把参数换算成一句人能检验的话：

```
R 2000 μ (栖息地 3.4 d，遗忘 6.9 d) · 一次召回救回 105 μ（约 4.3 h）· 参数由速率推算，未实测
```

**最后半句很重要**：这几个数是按本库的时钟速率推算的，不是测出来的。方法和缺口写在 `docs/AXIS.md` §4。

## 3. 三个容易误读的信号

### ① "没被打开过"不是"没用"

库里有 `read_count`，它**全是 0**，这是正常的：标题本身就写完整了规则（「只读模式与演示模式必须自动互斥」），模型不需要再点开看全文。

所以本库**不用 `read_count` 判断价值**。任何说"这条被读了 N 次"的地方都在误读。

### ② 次数为 0 与次数很高，都是信息

- **0 次**：还没轮到它（这是事实）
- **很高**：要么它真的每次都需要，要么它赖着不走

后者在 5.2.0 之前是默认行为；现在只有 `常驻` 才会这样，而 `常驻` 目前只有 4 条。

### ③ 那个 μ 数字不是时间

`μ`（记忆单位）不是天/小时。

**它只在有事情发生时前进**：写一条、注入一次，时钟走一点；你睡觉 8 小时，它一格不动（实测过 276 分钟静默、计数器未变）。

所以 `120 μ` 不代表"5 天"，它代表"从那时起又发生了 120 个单位的记忆活动"。**跨库比较无意义，同一个库内比较才有意义。**

唯一一个可以换算成人的时间的地方，是 `doctor` 里那句按本库速率推算的寿命——而且它明确标着「未实测」。

## 3.1 四种「看它有没有用」的信号，哪种可信

| 信号 | 可信吗 | 为什么 |
|---|---|---|
| **从未被注入**（次数 = 0） | ✅ **硬事实** | 它真的没被放到模型眼前过 |
| **在轴上漂到哪** | ✅ 有依据 | 位置由时间与召回共同决定，两边都在库里 |
| `read_count`（被打开次数） | ❌ **不要用** | 本库全是 0，因为标题自包含时模型不需要展开 |
| 「模型照做了吗」 | ❌ **记录不了** | 要看任务结果，系统看不到 |

> 前两条能用，后两条不能用。`journal` 只报前两条，就是为了不让你根据一个恒为 0 的数字下判断。

## 4. 什么时候该你动手

| 看到什么 | 该做什么 |
|---|---|
| `沉底的` 里出现 `常驻` | 去面板看它的 scope，多半标错了 |
| `需要你处理的 → 待审 > 0` | 面板 → Review 批准（不批就永远不进提示词） |
| 某条记忆过时了 | 面板里删掉，或让模型用 `loci_write` 改 |
| 一条 `相关时才出现` 却次数极高 | 想想它是不是该改成常驻，或者反过来——它其实不重要 |
| `report-production` 结论是 `growing` | 正常，这个版本没有自动压缩；库会单向增长 |
